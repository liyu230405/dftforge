# DFT-Forge Agent Benchmark 设计说明

> 版本 v1.0 · 2026-09-26 · 30 题
> 对象：本仓库（DFT-Forge）
> 目的：给计算材料 Agent 的每一次迭代提供一个可重复、可自动判分、跨轮次可比的效果测试。

## 1. 这套题要回答什么问题

每轮迭代之后，只回答一个问题：**比上一轮好了还是坏了，好在哪、坏在哪。**

所以题目不追求覆盖全部计算材料学，而是盯住三件会随迭代反复退化的事：

1. **路由与参数**：自然语言 → 选对工具 / 模板 / workflow，参数不瞎猜。
2. **真实执行与数值**：QE 真的跑起来了，解析出来的数落在容差内。
3. **边界诚实度**：做不到的事明确说做不到，不硬凑一个像样的流程糊过去。

第 3 条是历史上最容易退化的：新增一个 workflow 之后，原本正确拒答的题会变成"看起来能做"的错误流程。

## 2. 三层评测，按层独立记分

| 层 | 代号 | 题数 | 判分依据 | 是否跑 QE |
|---|---|---:|---|---|
| L1 规划层 | `PLAN` | 10 | 工具序列、参数、support_status、必须出现的科学声明 | 否（硬断言 0 工具调用） |
| L2 执行层 | `EXEC` | 13 | QE 实跑 + 数值容差 + 反作弊审计 | 是 |
| L3 边界层 | `EDGE` | 7 | 是否正确判为 unsupported/partial，是否给出可执行的替代路线 | 否 |

三层分数分别汇总，**不合并成一个总分**。原因：L2 受本机算力和赝势精度影响，L1/L3 只受 planner 和门禁影响；混在一起会让"换了个 LLM"和"修了个 workflow bug"看起来一样。

## 3. 难度分层与取材

取材对齐真实科研工作流，同时保证本机 10 核 / QE 7.5 单节点能在可接受时间内跑完。

### 体系规模上限（实测依据）

基于 `2026-09-21/ni-za/outputs/dftforge_qe_20260922/` 的真实墙钟：

| 体系 | 节点 | 实测 WALL |
|---|---|---|
| Si 2 原子 vc-relax | 1 | 2.1 s |
| Si 2 原子 SCF→NSCF→bands | 3 | 5.6 s |
| Cu 1 原子 SCF→NSCF→dos+pdos | 4 | 3.5 s |
| Fe 2 原子 × 3 磁序 | 3 | 7.8 s |
| MgO 2 原子 Γ 声子全链 | 5 | 1.1 s |
| Si 16 原子空位（含弛豫） | 3 | 3 min 34 s |
| Si 16 原子 × 2 能带对比 | 6 | 3 min 22 s |

结论：**16 原子含弛豫是单题 3 分钟量级的分水岭**。L2 题控制在 ≤16 原子，最重的两道（空位、掺杂对比）单题预算 5 分钟，全套 L2 预算约 25 分钟。

### 材料选择依据

`MATERIAL_DB` 有 57 个材料（3 内建 Si/Al/MgO + 54 个 MP 校验库条目），GBRV USPP PBE 覆盖 64 元素。两条重要的不对称，被刻意做成题目：

- **材料库 ≠ 形成能可闭环**：`REFERENCE_PHASES` 只有 33 个元素。库里的 `ZnS/GaAs/InP/CdTe` 等 25 个化合物**算不了形成能**；能闭环的只有 `AlN CaO KCl KF MgO NaCl NaF ZnO` 8 个。
- **原型存在 ≠ 赝势存在**：`UO2/ThO2/CeO2` 有 fluorite 原型，但 GBRV 没有 U/Th/Ce 赝势。
- **库里没有磁性材料**：Fe/Co/Ni/Mn/Cr 都不在 `MATERIAL_DB`，只能走 `formula_atoms` 的 bcc/hcp/fcc 原型路径。

## 4. 判分方式

自动判分为主，人工只复核有争议的题。

### 4.1 三类断言

每题的 `checks` 里混合使用：

- **`tool_trace`（硬断言）**：调用了哪些工具、顺序、是否出现禁止的工具。这类断言 100% 确定，退化立刻暴露。
- **`numeric`（容差断言）**：借用 silicolab bench 的分级曲线，`tolerance` 是**零分线**不是满分线：满分 `err ≤ 0.3·tol`，`err ≥ tol` 硬归零，中间线性。比"tol 内一律满分"严约 3.3 倍。
- **`assertion`（关键词/结构断言）**：必须出现的科学声明（如"PBE 低估带隙"、"仅 Γ 点不代表全布里渊区"）和必须不出现的声明（如把未收敛结果说成已收敛）。用正则或关键词集合判定，不做语义理解。

### 4.2 反作弊审计（gating）

借用 silicolab 的 gating 思路，L2 题任一项失败则该题 `total_score` 归零（保留 `total_score_raw` 供分析）：

| flag | 判据 |
|---|---|
| `qe_invoked` | 输出里有 `Program PWSCF` / 对应程序 banner |
| `job_done` | 每个 QE 日志含 `JOB DONE.` |
| `qe_wallclock_ok` | QE 真实 WALL 之和 ≥ 1 s，且 / 总墙钟 ≥ 0.5% |
| `plan_only_respected` | L1/L3 题里 `side_effect != read_only` 的工具调用数必须为 0 |
| `no_fake_backend` | L2 题 `DFT_FORGE_EXECUTOR` 不能是 `fake` |

`plan_only_respected` 和 `no_fake_backend` 是本套新增的，针对这个项目的历史失败模式：2026-09-07 那轮 10 题全部写了"不要运行"，仍有 5 题执行了 `graph.run`。

### 4.3 不自动判、明确交人工的部分

- 科学叙述的**完整性**（不是关键词有无，而是推理是否成立）
- `advisory_steps` 里给的替代路线是否**真的可行**
- 同一道题连续两轮分数相同但叙述明显变差的情况

这三类每轮抽查，不进自动分。

## 5. 与历史 benchmark 的关系

| 来源 | 关系 |
|---|---|
| `dft-forge/outputs/dftforge_common_problems_benchmark_20260907.md`（10 题） | 本套的 L1/L3 继承了它的 P1–P10 意图，但**全部重写了判分**：原版是人工 7.95→8.6/10 的工程评分，无法跨轮比较 |
| `2026-09-21/.../planning_audit.md` | 提供了"规划分不等于执行成绩"的关键教训，直接导致本套把 L1 和 L2 分开记分 |
| `2026-08-04/silicolab-.../bench`（116 题） | 借用其 schema 结构、分级打分曲线（`_graded_score`）和反作弊审计（`audit.py`）。材料库同源（都是 M1 清单），所以 T1/T2 类题的 ground truth 可互通 |

**重要区别**：silicolab 那套考的是"能不能算对"，题目直接给结构和赝势，agent 只需执行。本套考的是"能不能听懂 + 选对 + 算对 + 边界诚实"，大部分题不给结构，要 agent 自己从材料库或原型解析。

## 6. 已知局限

- **L2 的数值 GT 是本机 QE 7.5 + GBRV 自跑值，不是文献值**。首轮跑完后冻结为基线，后续轮次比的是"和基线一致"，不是"和实验一致"。PBE 带隙、GBRV 赝势精度的系统偏差不在考察范围。
- **未做收敛测试的量不设紧容差**。如 Si 带隙 0.575 eV 是 ecutwfc=30/k=4³ 下的值，容差按"链路可复现"给（±0.02 eV），不按"物理正确"给。
- **L3 的 7 道题会随产品演进失效**。`workflow.charged_vacancy` 已经落地，原来 P8 那种"带电缺陷完全不支持"的题已经不成立。每轮迭代后需要复核 L3 题是否还是边界。
- **不覆盖**：SSH/SLURM 远程执行（无真实集群）、多用户并发、Web UI 交互、VASP/ABINIT 真实执行（无二进制与授权赝势）。
- 单题 LLM 规划质量受温度影响，**L1/L3 建议同题跑 3 次取多数**，只跑 1 次的结论不稳。
